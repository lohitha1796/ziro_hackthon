Every computed row is derived from the current application state, not hard-coded. Rows marked design are properties of the implementation that cannot be observed from a single session.

Dataset and scope

Sources are retrieved and scored; the authority gate then rejects anything that is not active and authoritative. Superseded, marketing and prior-response documents are kept in the trail so their rejection is auditable.

How to demonstrate

  1. Open Mock portal and show the open questionnaire (15 questions) plus the 2023 prior submission.
  2. Click Run agent: steps 01-03 collect, plan and retrieve. Nothing is written.
  3. Open Review queue: proposed answers with citations, withheld items and reviewer tasks.
  4. Approve or edit the items you agree with, then Submit approved to portal (step 04).
  5. Click Verify against portal (step 05), then read Results (step 06).
  6. Open Test cases and run TC1-TC4, then export the evidence bundle.
Test harness note. Inside a test run the human approval is simulated by a clearly-labelled test reviewer that only ever approves items the agent already marked as answered. Real runs always require a named human reviewer, and the portal is never written before approval.

Questionnaire

Policy library

Only authoritative + active sources may back an answer. Superseded, draft and non-authoritative documents are still retrieved and scored so the rejection is visible in the evidence trail. Expand a row to inspect its content.

Certification registry

The single source of truth for certification claims. A certification that is not held here may never be claimed, regardless of what other documents say.

Evidence coverage

Sources considered and rejected

Every candidate source that scored against a question but failed the authority gate, with the machine-readable reason. A superseded document is never authoritative even when it is a closer match.

Review queue

Nothing is written to the portal until a named reviewer approves an individual item. Items marked unknown or needs review carry no citation and are never approvable: they stay open with a reviewer task. Editing an answer changes what will be written, and verification re-checks the edited text. A bulk Approve all cited answers only fills in items that are still undecided - it never overwrites an answer you have explicitly rejected.

Official test cases (TC1-TC4)

Each scenario is executed in a freshly seeded environment with a simulated reviewer. The record keeps the scenario input, the expected result, the actual result, the evidence trail and an explicit note about any difference. Run test re-runs a single case.

Audit log

Every event carries an event id, a timestamp, the actor, the action and, where a state change occurred, the previous and new state.

Reasoning mode

The deterministic engine is always available. The LLM is used only to classify the question, rerank candidate passages and phrase the answer from supplied facts. Every model response is validated before use.

The key is stored in localStorage under your own browser profile, is never written to the audit log or to exported evidence, and is never required for the demo. For a deployed build put the key on a server-side proxy instead.

 

Thresholds and transport

Switching transport to http makes the same pipeline call real URLs - useful if you deploy the mock portal as a service. It is off by default so the demo works from the file system.
